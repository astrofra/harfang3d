# HGS2: quantized, compressed Gaussian assets

Status: implemented format contract. HGS2 replaces HGS1; no compatibility reader is retained. Recompile existing `.hgs` assets with `gsplatc` or `assetc`.

## Pipeline and storage choice

`gsplatc` imports PLY, `.splat`, or supported SPZ into the canonical CPU Gaussian representation, applies the selected count/SH/normalization options, then encodes HGS2. Quantization is therefore available directly from PLY; SPZ is not an intermediate requirement.

```json
{
  "profiles": {
    "default": {
      "type": "gaussian-splat",
      "max-count": 250000,
      "sh-degree": 3,
      "normalize": true,
      "storage": "quantized"
    },
    "reference": {"storage": "float32"}
  }
}
```

`storage` accepts `quantized` (default) or `float32`. The CLI equivalent is `--storage quantized|float32`. Both choices use the same HGS2 header, block table, integrity checks and zlib compression. `float32` is a lossless reference representation of the imported canonical data, not an HGS1 compatibility option. Profile storage changes participate in assetc incremental compilation.

The native loader decompresses one block at a time and reconstructs the existing float arrays before upload. Lua and GPU shader APIs do not change. Disk size and file I/O decrease; canonical CPU/GPU allocations remain unchanged. This implementation does not provide streaming or direct rendering from compressed attributes.

## Quantization

Each block contains up to 256 splats, in retained source order. Ranges are derived independently for each block, so PLY colors and harmonics outside SPZ's fixed representable range do not need clipping.

| Attribute | Stored representation | Reconstruction |
|---|---|---|
| Position | Three unsigned 16-bit values | Linear interpolation of the block's per-axis bounds |
| Opacity | Unsigned 8-bit value | Value divided by 255 |
| Scale | Three unsigned 8-bit values | Logarithmic interpolation of positive per-axis scale bounds |
| Rotation | 32-bit smallest-three quaternion | Reconstruct the positive largest XYZW component, normalize, reorder to canonical WXYZ |
| DC | Three unsigned 8-bit values | Linear interpolation of each channel's block range; values remain SH coefficients |
| Higher SH | Three signed 8-bit values per coefficient | Value divided by 127, multiplied by the block's per-coefficient/channel absolute maximum |

Round to nearest. Signed SH codes use -127 through 127; -128 is invalid. Constant ranges encode zero and reconstruct the constant. Zero SH ranges encode zero. No gamma conversion is introduced. Canonical vector padding reconstructs as zero.

Position/DC interpolation uses double intermediates to handle finite float ranges without subtraction overflow. Scale metadata stores original **linear** float endpoints; logarithms and exponentiation use double arithmetic, with reconstructed scales bounded by those endpoints. This avoids losing valid extreme scale endpoints through rounded float log metadata.

Each block stores 72 bytes of position/scale/DC ranges plus 12 bytes per non-DC coefficient for SH ranges. Attribute streams occupy `N * (17 + 3 * non_dc)` bytes. SH3 therefore uses 62 attribute bytes per splat, plus range/table overhead, versus 304 bytes in the canonical float representation. SH0 uses 17 attribute bytes versus 64 canonical bytes. Compression applies after quantization.

Error bounds before float rounding:

- Position: block axis extent / 131070.
- Opacity: 1 / 510.
- DC: block channel range / 510.
- Higher SH: block coefficient/channel absolute maximum / 254.
- Scale: relative error at most `exp(log(max/min) / 510) - 1` for that block axis.
- Rotations use three signed 9-bit magnitudes over the smallest-three range; measured error is reported as sign-equivalent quaternion L2 distance.

`gsplatc` reports the actual reconstructed maximum errors (Euclidean distance for position), raw block bytes and final file bytes. Ranges include every retained value, so no intentional saturation is performed. Outliers can increase errors for the rest of a block; use the `float32` profile when the quantized result is unsuitable. Information already lost in a source SPZ cannot be recovered.

## Binary layout

All integers and floats are little endian. Scalar floats are IEEE 754 binary32. Payload blocks use the zlib wrapper around DEFLATE, generated by existing miniz at level 6. There is no new compression dependency.

### Header (128 bytes)

| Offset | Type | Meaning |
|---:|---|---|
| 0 | byte[4] | `HGS2` |
| 4 | u16 | Major version: 2 |
| 6 | u16 | Minor version: 0 |
| 8 | u32 | Endian marker: `0x01020304` |
| 12 | u32 | Header length: 128 |
| 16 | u64 | Exact total file length |
| 24 | u32 | Flags: antialiasing 1, normalized 2, higher SH 4 |
| 28 | u32 | SH degree, 0-3 |
| 32 | u32 | Retained splat count |
| 36 | u32 | Original source count |
| 40 | u32 | Storage: 0 float32, 1 quantized |
| 44 | u32 | Maximum splats per block: 256 |
| 48 | u32 | Block count: ceil(retained count / 256) |
| 52 | u32 | Table entry length: 32 |
| 56 | u64 | Table offset: 128 |
| 64 | u64 | First payload offset: 128 + 32 * block count |
| 72 | f32[3] | Retained position bounds minimum |
| 84 | f32[3] | Retained position bounds maximum |
| 96 | u64 | Sum of uncompressed block lengths |
| 104 | u32 | CRC32 of all 128 header bytes with this field zeroed |
| 108 | u32 | CRC32 of the complete block table |
| 112 | byte[16] | Reserved, zero |

### Block table entry (32 bytes)

| Offset | Type | Meaning |
|---:|---|---|
| 0 | u64 | Absolute compressed payload offset |
| 8 | u32 | Compressed block length |
| 12 | u32 | Uncompressed block length |
| 16 | u32 | Splats in this block |
| 20 | u32 | CRC32 of the uncompressed block |
| 24 | u64 | Reserved, zero |

Blocks are consecutive without gaps, overlap, or trailing bytes. Every block except the last contains 256 splats. Expected uncompressed lengths are derived from count, storage and SH degree, not trusted solely from the table.

### Quantized raw block

Metadata comes first, in this exact float32 order:

1. Position minimum XYZ, then maximum XYZ.
2. Linear scale minimum XYZ, then maximum XYZ.
3. DC minimum RGB, then maximum RGB.
4. Higher-SH absolute maxima: coefficient-major RGB, excluding DC.

Then come separate attribute streams in this exact order:

1. Position: `N * 3` u16 values, XYZ per record.
2. Opacity: `N` u8 values.
3. Scale: `N * 3` u8 values, XYZ per record.
4. Quaternion: `N` u32 values.
5. DC: `N * 3` u8 values, RGB per record.
6. Higher SH: `N * non_dc * 3` i8 values, coefficient-major RGB per record.

Quaternion packing uses bits 30-31 for the largest XYZW component's index. Negate all components first if that component is negative. Visit the other component indices in descending order, consuming bits 0-9, 10-19 and 20-29 respectively. Each slot contains a 9-bit magnitude and one sign bit, representing `sign * magnitude / (511 * sqrt(2))`. Reconstruct the largest component from the unit-length constraint.

### Float32 raw block

The first `N * 16` floats are canonical base records: position/opacity, linear scale/zero, WXYZ quaternion, DC/zero. They are followed by `N * non_dc * 4` floats: coefficient-major RGB/zero, grouped per splat. Compression preserves these bits exactly.

## Validation and limits

The reader rejects unknown magic/version/storage/flags, invalid counts, noncanonical table layout, nonzero reserved fields, inconsistent bounds, nonfinite/inverted quantizer ranges, nonpositive scales and invalid quaternions/SH codes. Header, table and raw block CRCs are checked. Each compressed block must reach stream end, consume its exact compressed length and produce its exact expected raw length.

File bytes and expanded canonical float data are each capped at 512 MiB; count remains 1-1,048,576. Header/table structure is validated before large canonical allocations. Blocks decompress into bounded temporary buffers. Source import validation and source byte budgets remain unchanged. Writer validation and serialization complete before the destination file is opened.

## Verification

`harfang/tests/gaussian_splat_hgs2.py` is an independent Python/zlib format inspector used only by developer tests. The native regression harness covers both storage modes, block boundaries, degenerate ranges, error bounds, deterministic encoding, malformed headers/tables/payloads and legacy rejection. The GPU probe exercises both storage modes with the existing multi-model, depth, SH and lifetime checks. Assetc tests cover storage metadata, profile overrides, validation and incremental rebuilds.

Real-asset measurements and screenshots are recorded in [native progress](GSPLAT_NATIVE_PROGRESS.md). Runtime tutorials and production conversion require no Python.
